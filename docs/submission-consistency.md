# 제출본과 현재 프로젝트의 정합성

확인일: 2026-09-05

제출한 10쪽 PDF는 표지에 명시된 **2026-09-04 검증 기준**의 기록이다. 이번 확인에서는 전체 본문을 읽고 화면과 수치가 담긴 3, 5, 8, 9쪽을 렌더링해 대조했다. 제출본은 수정하거나 다시 생성하지 않았다. 현재 저장소와 데모는 제출 이후 개선을 포함한다.

핵심 기능과 공개 API 범위에 충돌은 없다. 다만 화면의 탐색 명칭과 토큰 견본, 검증 수치는 제출본과 다르다. 제출본의 캡처와 수치를 현재 실행 결과로 해석하지 않도록 아래에 차이와 설명을 남긴다.

## 검증 출처 설명의 보충

8쪽의 Source revision, Run ID, Artifact digest 설명은 검증 근거의 추적 구조를 요약한다. 실제 구현은 내용 해시로 현재 소스를 확인하고 최신 **소스 변경 커밋**을 별도로 기록한다. 근거만 갱신한 커밋의 HEAD와 화면의 Commit은 다를 수 있다.

Run ID는 CI에서는 GitHub 실행 ID이며, 로컬에서는 보고서를 생성한 프로세스의 `local:<pid>`다. 따라서 서로 다른 로컬 검사 보고서가 모두 같은 Run ID를 갖는다는 뜻은 아니다. 각 보고서의 출처와 해시를 검증한 뒤 통합 근거를 생성하며, 리허설 기록은 검토 문맥과 통합 근거의 소스 리비전, 소스 커밋, 해시에 결합된다. 보안 감사에는 동일한 의존성 스냅샷의 24시간 이내 성공 기록을 재사용할 수 있는 별도 규칙이 있다.

제출 당시 측정값을 새 측정값으로 덮어쓰거나 과거 PDF를 다시 만드는 대신, 현재 검증 근거를 [별도 커밋 절차](release-and-compatibility.md#소스와-검증-근거-커밋-순서)로 기록한다. 구체적인 수정과 측정 조건은 [검토 후 개선 사항](review-improvements.md)을 참고한다.
