# 디자인 시스템 확장 로드맵

현재 구현은 변경 전달과 검증 구조를 깊게 확인하기 위한 개인 PoC입니다. 색상, 간격, 모서리 반경을 다루는 DTCG 핵심 경로 31개와 React 컴포넌트 6개만 포함합니다. 구성 요소 수를 실제 제품 규모처럼 보이게 늘리기보다, 소비 요구와 검증 기준이 정해진 순서대로 확장합니다.

## 우선순위와 완료 조건

| 순서 | 확장 영역 | 먼저 확인할 제약 | 완료 조건 |
| --- | --- | --- | --- |
| 1 | 타이포그래피 | 한글과 라틴 혼용, 플랫폼별 폰트 대체, 동적 글자 크기 | 역할 기반 글자 토큰, 웹과 네이티브 산출물, 200% 확대와 줄바꿈 회귀 검사 |
| 2 | 엘리베이션 | 다크 모드, 고대비 모드, 그림자 비지원 환경 | 계층 의미를 이름에 담은 토큰, 테두리 대체 표현, `forced-colors` 검증 |
| 3 | 모션 | 멀미 유발 가능성, 플랫폼별 easing 차이 | duration과 easing 토큰, `prefers-reduced-motion` 대체 동작, 전환 상태 테스트 |
| 4 | 밀도 | 터치 영역과 정보 밀도의 충돌, 웹뷰 입력 방식 | compact와 comfortable 모드, 최소 조작 영역 유지, 모바일 및 키보드 검증 |
| 5 | 컴포넌트 확대 | 실제 소비 흐름과 유지보수 비용 | 두 개 이상 소비 사례, 접근성 계약, 공개 API 기준, 문서와 마이그레이션 경로가 함께 준비된 항목만 추가 |
| 6 | 실제 조직 지표 | 저장소 표본과 운영 데이터의 혼동 | 저장소 밖의 소비 팀, 버전, 마이그레이션 기간을 별도 데이터 소스로 수집하고 분모와 기간을 공개 |

## 의도적으로 미룬 항목

- 타이포그래피, 엘리베이션, 모션, 밀도는 토큰 이름만 먼저 추가하면 플랫폼별 의미가 어긋날 가능성이 있어 현재 범위에 포함하지 않았습니다.
- iOS와 Android는 토큰 산출물만 생성합니다. 실제 네이티브 컴포넌트는 각 플랫폼의 접근성 및 렌더링 검증 환경이 준비된 뒤 별도 패키지로 다룹니다.
- 실제 조직 도입률은 이 저장소에서 만들 수 없습니다. 현재 소비 예제는 분석 도구의 동작을 증명할 뿐 조직 성과를 대신하지 않습니다.
