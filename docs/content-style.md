# 제품 문구 작성 원칙

이 문서는 화면과 내부 문서의 언어 및 용어를 일관되게 유지하기 위한 기준입니다.

## 언어 기준

- 개발자용 Studio 화면은 영어를 사용합니다. 소비 제품 예시는 한국어를 사용합니다.
- 코드 식별자, API 이름, 패키지 이름, 표준 이름은 원문을 유지하고 코드 서식으로 표시합니다.
- 한 문장 안에서 같은 의미의 한국어와 영어를 섞지 않습니다. 처음 보는 기술 용어는 필요한 경우 한국어 설명과 원문을 함께 씁니다.

## 용어 기준

| 사용 | 피해야 할 표현 |
| --- | --- |
| 테스트 픽스처 | fixture만 단독 사용 |
| 매니페스트 | manifest를 일반 명사처럼 사용 |
| 승인 기록, 리허설 기록 | receipt, 영수증 |
| 소스 리비전 | source revision |
| 검증 항목, 검증 단계 | gate |
| 산출물 | artifact를 일반 명사처럼 사용 |
| 제공자 | provider |
| 지원 중단 예정 | deprecated |
| 하위 호환성이 깨지는 변경 | breaking change |
| 저장소 표본 커버리지 | 실제 조직 도입률, 도입률 100% |

## 화면 문구 기준

- 버튼은 `Run rehearsal`, `Complete review`처럼 동사와 목적어로 씁니다.
- 상태는 `Review required`, `Rehearsal complete`처럼 짧고 구체적으로 씁니다.
- 실제 실행 범위를 과장하지 않습니다. 로컬 검증, CI 검증, 외부 배포를 명확히 구분합니다.
- 검증용 소비 앱 수치는 분모와 범위를 같은 문맥에 표시하고 실제 조직의 도입 성과로 표현하지 않습니다.
- 가운뎃점은 짧은 메타데이터 구분에만 사용합니다. 문장에서는 쉼표나 접속 표현을 사용합니다.
- 접근성 이름은 화면에 보이는 동작과 같은 언어로 작성하고, 대상까지 구체적으로 밝힙니다.

## 검토 방법

문구를 바꾸면 단위 테스트, 시각 회귀, axe 검증, 생성 문서 최신성 검사를 함께 실행합니다. 생성 파일은 직접 수정하지 않고 원본 레지스트리나 생성 스크립트를 고칩니다.
